The basic loop

Plan, build, check, review. What review does not accept goes back as a revision, and only reviewed work is committed.

    Four ideas, in motion

    The process lives in code. The agents can change.

    People approve

    The plan is a document. Editing it is the decision.

    Before any code is written, an agent drafts a plan that a person can read. The flow stops and waits. Approve it and the work starts. Send it back and the agent revises it, keeping your edits.

    Wait for a person

    The run pauses on the plan until you answer.

    Left behind

      Agents in parallel

      One epic, many agents, one branch.

      The plan splits an epic into stories that say which files they own and what they depend on. Independent stories are built at the same time, each in its own copy of the repository. A judge scores every story before it merges.

      Stories, three at a time

      Story 1 lays the ground. Stories 2 to 4 run together. Story 5 waits for them.

      Left behind

        Files are the state

        Stop at any point. Pick up where it stopped.

        Progress is written to files in the repository, not held in an agent's memory. When an agent goes offline or a laptop closes, the next run reads the files, keeps what was done, and continues.

        Interrupt and resume

        Halfway through, the agent drops out. Rerun to continue.

        Left behind

          Any agent, any seat

          Swap the agent. Keep the process.

          A workflow asks for roles: someone to plan and judge, someone to write code. Any coding agent fills a role, hosted or running on your own machine. The steps, the checks and the record stay the same.

            Modernization

            Read the old system once. Build the new one from what people approved.

            Agents turn a legacy code base into a specification: what each program does, as rules and scenarios, each traced to its source. People approve it. The new system is then built from that specification on the other side of a clean-room wall, where the old code cannot be reached, and proven equivalent by replaying recorded behaviour.

            Legacy to target

            The process is the same for every technology. The kit you pick supplies the knowledge.

            Left behind

              Kit

              Everything one migration path needs, as files: how to read the old stack, the starter for the new one, and the recipes in between. A team adds a technology by writing a kit, not by changing the engine.

              Pack

              The contract inside a kit: which files are programs, which checks must pass, how a judge scores, what "equivalent" means. Review adds what it learns back into the pack.

              Pattern card

              A short recipe that translates one idiom from the old stack to the new. Each agent gets only the cards that match the code in front of it.

              Not every program deserves a port

              Some legacy code is dead, and some behaviour the new platform already provides. So the specification is first distilled, with a person, into an epic brief: what is in scope, what is dropped, what is deferred. Once it is approved, the parallel stories above build that slice.
