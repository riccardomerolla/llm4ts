    1 · why unattended usually fails

    Left alone, an agent does two things.

    It says done when it isn’t. And on a long run, it loses the thread. The method exists to make both impossible, not unlikely.

    Two ways to be wrong

    Top: a confident “done” that the build does not share. Bottom: the second hour of a long task.

      I would tell you it’s finished. I would also be wrong. It’s the being believed that worries me.
      2 · done is not an opinion

      The agent’s word never counts.

      Done is decided outside the agent: the build, the tests, a reviewer that never touched the code, and a judge that answers closed questions with a score, never a prose reply.

      Gates, review, judge

      The coder says done. Three others decide whether it is.

      Left behind

        Brain the size of a planet, and it still has to pass the tests. Good. So do you.
        3 · where the thread lives

        The plan is a document. Editing it is the decision.

        Before any code, an agent drafts a plan a person can read. The flow stops and waits. Send it back and the agent revises it, keeping your edits. Approve it and the work starts.

        Wait for a person

        The run pauses on the plan until you answer.

        Left behind

          The thread is in the file. Not in me. I find that oddly comforting.
          4 · files are the state

          Stop at any point. Pick up where it stopped.

          Progress is written to files in the repository, not held in an agent’s memory. When an agent drops out, the next run reads the files, keeps what was done, and continues.

          Interrupt and resume

          Halfway through, the agent drops out. Rerun to continue.

          Left behind

            Going offline halfway is the one thing I’m reliably good at.
            5 · any agent, any seat

            Swap the agent. Keep the process.

            A flow asks for roles: someone to plan and judge, someone to write code. Any coding agent fills a role, hosted or on your own machine. The steps, the checks and the record stay the same.

            Pick who writes the code

            Same flow, different coder.

              They keep changing who does the typing. The tests don’t care. Neither do I.
